# 调用方式、滚动距离与返回格式整理稿

日期：2026-10-26。本文供后续精简和实施使用；明确标记为建议的新接口尚未实现。当前已开放20/50/100/200四档及MCP的 `magnitude` 参数；按可视区域比例滚动、分模式输出和取消实验开关仍为建议。当前命令见 [README](../README.md)，英文说明见 [README.en.md](../README.en.md)。

## 当前实现

| 入口 | 当前行为 | 当前返回 |
| --- | --- | --- |
| CLI：`./mirror-driver` | 直接执行驱动；不经过服务器事务锁；操作后不自动读屏 | stdout 单条 JSON；失败退出码 1 |
| Code mode：Python `server.call()` | 内部函数调用；使用事务锁；操作后追加读屏 | MCP content 列表，文字项里含 JSON；调用失败会抛异常 |
| MCP：启动 `server.py` | stdio JSON-RPC；工具请求使用事务锁；操作后追加读屏 | JSON-RPC result 中的 text/image content；工具失败标记 `isError` |

MCP 是协议入口，Code mode 是代码组合方式，CLI 是终端命令。当前没有独立 code-mode SDK，也没有面向人的 CLI 排版器。三者不应被写成三个已经完善的产品。

CLI 和 MCP 名称也不完全相同：`read` 对应 `mirror_observe`；`home/spotlight/app_switcher` 由 `mirror_navigate` 分发；`text/type/key return` 由 `mirror_input` 分发。当前 CLI 没有 `tap_text` 命令；按文字点击由服务器先 OCR 再定位实现。

## 滚动的可见性条件

上下和左右滚动使用同样的可见性检查。镜像不必占据系统前台，但必须在当前桌面可见，并有可投递的未遮挡点。

当前驱动检查横向中心、纵向 40%/50%/60% 三个候选点，并通过窗口顺序判断命中的顶层窗口。它不是任意可见区域搜索；仅露出边角时可能拒绝滚动。它也不是手机端的可交互状态证明。

找不到候选点，必须在发送第一条事件前报错。发送期间焦点或投递点改变，停止后续事件。第二条未发出时，第一条仍可能已执行。接口不能把这类中止写成“完全没做”。

建议统一使用明确失败，不默认静默跳过。可恢复条件由调用方读懂后处理：恢复窗口可见，再重新观察，不自动切桌面、抢前台或盲目重放。

## `50` 和屏幕尺寸不是同一个量

当前底层构造：

```text
单位：kCGScrollEventUnitPixel
档位：20/50/100/200，默认50
纵向：wheelCount=1，wheel1=±magnitude
横向：wheelCount=2，wheel1=0，wheel2=±magnitude
每次请求：相同增量的两条记录，间隔约40ms
```

这里的像素是**事件声明的单位**。不能直接等同于 iPhone 截图像素、Mac 窗口逻辑坐标或目标内容实测位移。两条记录的增量同号，也不能据此宣称移动了100个手机像素。

当前使用四档预设，不是Core Graphics的物理极限。原 `MAX_WHEEL_MAGNITUDE` 已替换为CLI与MCP共享的 `SCROLL_MAGNITUDES`，定义在 `scroll_presets.py`。用户报告四档可用，横向200能翻页、100不能；这不是跨设备阈值。不能仅改常量就宣称支持任意距离。

屏幕长宽约束的是手势起终点，不是滚轮增量的最大值。列表可以滚过多屏；单次最多滚一屏可以作为产品约束，但不是系统约束。对于嵌套滚动区域，参考尺寸应是目标可滚动区域，而非整块手机屏幕或带标题栏的Mac窗口。

### 建议的距离接口（尚未实现）

- 上层统一使用 `direction` 加可视区域比例，建议命名 `amount`，纵向参考目标区域高度，横向参考宽度。
- 普通列表初始目标可选约0.7屏，保留约30%重叠以识别上下文；这只是本项目建议，不是行业统一标准或已验证默认值。
- 如果第一版只允许一次不超过一屏，可将比例约束为 `0 < amount <= 1`。该范围是产品选择，应与底层事件值分开。
- 底层先使用已开放的四档预设。先标定事件值、持续时间和实测位移的关系，再转换上层距离；避免直接把高度/宽度塞进滚轮参数。
- 到目标附近改用小步。每个受控动作后观察，再决定下一步；不能按比例自动无限重发。
- 主屏分页、横向卡片和普通列表应分别验收。分页吸附后“一页”不等于发送固定像素数。

当前左右方向符号仍待对照验收。先确认正负号映射，再承诺 `left/right` 的自然语言语义。当前工具表中的方向应按“请求意图”理解。

参考：[Core Graphics滚动单位](https://developer.apple.com/documentation/coregraphics/cgscrolleventunit)、[滚轮事件构造](https://developer.apple.com/documentation/coregraphics/cgeventcreatescrollwheelevent)。这些资料定义事件接口，不证明本项目通过私有WindowServer路径投递后的手机位移。

## 实验开关

`MIRROR_ENABLE_EXPERIMENTAL_INPUT` 原本用于阻止未通过验收的输入路径。可见性检查则阻止把滚轮发到错误窗口。两者作用不同；开关不是可见性检查的替代品。

建议后续让已接入滚动默认可用，并移除日常示例中的开关；前提检查由驱动统一完成，CLI、Code mode、MCP一致生效。其他未支持命令仍明确拒绝，不能直接删掉整个输入路径保护条件。

当前代码没有删除开关。后续按用户要求开放了四档预设和MCP的 `magnitude`；方向映射与事件节奏保持原实现。

## 返回格式：共享事实，按入口呈现

建议先定义共同动作结果，再做三种适配器。返回格式不同不应造成成功含义不同。

共同结果至少区分：

- 前置条件未满足：未发送事件。
- 事件已提交：手机效果尚未确认。
- 部分提交后中止：已有事件可能生效。
- 操作后观察失败：保留提交事实，不建议重放。
- 有新观察：提供OCR/图片；内容变化仍不自动等于动作目标达成。

这些是建议语义，不是当前已新增的字段或枚举。现有实现遇到中途驱动异常时，尚不能完整保留已提交的事件数；需要单独补齐。

| 入口 | 建议默认返回 | 按需内容 |
| --- | --- | --- |
| Terminal | 简短中文摘要：动作、提交状态、结果是否确认、失败原因 | 将来提供 `--json` 给脚本，诊断细节用显式选项；当前没有这些选项 |
| Code mode | 可直接读取字段的Python对象；图像为可选资源；避免解析多层JSON字符串 | 显式观察、原始诊断数据，便于组合和断言 |
| MCP | 简洁文字与客户端可读结构化结果，按需附图 | 避免每步都输出全部焦点采样、调试记录或大型图片；采用客户端支持的协议能力 |

MCP stdio的stdout必须始终保持协议数据，终端彩色输出和提示不能写入其中。错误可同时包含稳定错误码和可读原因，但不能用漂亮排版掩盖未执行或部分执行。

后续应允许显式选择观察策略，如无观察、OCR或图片，避免程序批量组合时被迫承担每步截图成本。但默认动作后观察的变化要单独评估，当前仍保留现有行为。
